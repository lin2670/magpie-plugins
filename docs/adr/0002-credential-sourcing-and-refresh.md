# 登录态维护：复用优先，三级来源（桌面端凭据 / agent2api 导入 / 手动）

---
status: accepted
date: 2026-10-14
---

四家服务都要以用户自己的登录态访问上游，各家续期机制不一（小浣熊、Accio 有 refresh token 可自动续期；CatPaw、Loomy 无续期接口）。我们决定**不重实现登录流程**，按三级来源取得与维护凭据：① 有桌面端凭据可读的（妙手）由插件直接读取、随桌面端登录自动刷新；② 其余服务（小浣熊 / Accio / Loomy）先从参照实现 agent2api 的现有账号一次性导入；③ 兜底走 magpie 的手动登录入口。能自动续期的由插件在凭据层自动续期；无续期的（CatPaw / Loomy）过期后按 ①②③ 重新取得。账号按 magpie 惯例支持多账号，每日任务逐账号执行。

## Considered Options

- **在插件里重新实现各家登录（扫码 / 验证码 / OAuth）**：工作量大、易被上游改版打断，且多数服务没有面向第三方的登录开放接口。
- **只支持手动粘贴 token**：最简，但可维护性差（token 短期过期、用户操作频繁）。

## 修订（2026-10-15）：Loomy / AutoClaw 例外，重实现手机验证码登录

status 不变（accepted）。**Loomy 与 AutoClaw 国内版两家重实现了手机验证码登录**，作为 ①②③ 之外的第四来源（`agent-send-code` → `agent-login` / `checkCode`，协议见侦察笔记），与导入、手动粘贴并列出现在 magpie 登录方式里。

- **动机**：这两家的 session 短（Loomy 14 天、AutoClaw JWT 数小时），agent2api 里又只有一份账号——导入与手动粘贴都救不了「长期使用」，只有插件自己能登录才能让多账号长期自持；且两家登录协议都是**纯短信验证码两步**（无扫码 / 滑块 / OAuth），是四家里最容易稳定复刻的形态。
- **边界（仍是红线）**：只做"发验证码 + 验证码换 session"这两步，不碰风控（遇验证码图/滑块走 `captcha` 通道）；其他家（小浣熊 / CatPaw / 任何 OAuth 流程）仍按原三级来源，不重实现。
- **代价**：验证码登录路径要随上游改版维护（与被否选项里指出的风险相同，接受此代价换长期自持）。

## 修订（2026-10-16）：小浣熊 / CatPaw 补网页登录，四家全部「无外部依赖可登录」

发布准备时确认了硬约束：npm 包的用户大多没有 agent2api，「从 agent2api 导入」不能作为唯一可用的登录方式。因此给小浣熊与 CatPaw 各补一条**网页登录**（协议移植自 agent2api 的 `providers/raccoon/oauth.rs` 与 `login/catpaw.rs`，均为已实测实现），作为与导入、手动粘贴并列的来源。至此四家全部可零外部依赖完成登录：小浣熊=官方授权页授权码换token（用户粘贴 `office-raccoon://` 回调，state 逐字校验）；CatPaw=login-config 取入口 + **poll-token 轮询**（官方客户端 Promise.race 的兜底通道，服务端对服务端，无需 loopback 监听、不受浏览器 PNA 拦截）；Loomy/AutoClaw=此前已转正的短信验证码。

- **动机**：市场分发后登录方式即产品能力；妙手「依赖桌面端凭据」使无妙手的用户只能粘贴 token，长期可用性差。
- **边界（红线不变）**：只做「取授权/等回调/换凭证」，不碰风控；CatPaw 轮询超时 3 分钟给可读报错。
- **代价**：两条网页登录链路要随上游改版维护（同前两条修订，接受）。

## 修订（2026-10-16，之二）：新手任务并入 checkin

agent2api 的一次性新手福利（Loomy 8 任务 10000 分、小浣熊 desktop/mobile 两条首登奖励各 3000）迁移进插件：**随首次签到自动补领**，结算状态写进账号记录（loomy `onboardingSettled` / raccoon `onboardingGrants` 台账），之后每次签到零请求跳过——与 agent2api「一次性福利不进每日调度、签到后自动补领一次」的语义一致，只是把「签到中心快照 + 记忆」简化成账号记录上的一个字段。

- **动机**：市场分发后新用户拿新号注册，新手福利不领就是白丢（Loomy 一万分等于两天每日赠送）；插件用户没有 agent2api 的手动补领入口。
- **语义保持**：① loomy 8 key 逐字照抄客户端注册表，未知 key 上游拒绝；单 key 失败不阻断，下轮签到重扫，全清后落 `onboardingSettled`。② raccoon 无只读状态口，照 agent2api 以本地台账为准：一次请求无论 `granted` 真假都算落定（两种都代表奖励已裁决），落定后永不再发。③ magpie 托管的 checkin 调度本就逐账号执行，无需额外开关。
- **代价**：两条补领链路随上游改版维护（同前，接受）。

## Consequences

- 插件需提供凭据的导入 / 重读入口（本地文件读取 + 一次性导入），而非只依赖交互式登录。
- 妙手以"随桌面端登录自动刷新"为常态（重开妙手即自愈）；Loomy 无续期接口是已知短板，过期只能重登后重新导入——**修订后 Loomy 可直接在插件里重新短信登录，此短板缓解**。
- 出网代理池（参照实现内置）v1 不移植；先用系统网络与 magpie 既有代理机制。
- 多账号 + 逐账号每日任务为默认行为，无需额外开关。
